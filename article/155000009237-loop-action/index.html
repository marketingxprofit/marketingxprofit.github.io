Loop Action

The Loop action in MxP Workflows repeats actions for every item in a list or every number in a range. Learn how to configure a Loop, map item data, choose an execution mode, and review results for each iteration.

What Is the Loop Action?


The Loop action runs a group of workflow actions once for each item in a list or once for each number in a range. Use it to process multiple records from one trigger without duplicating actions or writing code.

For example, a webhook containing three service requests can trigger a Loop that creates a separate opportunity, task, and note for each service.

Key Benefits of the Loop Action

Loop makes it easier to process multiple records within one workflow.

  • Process multiple items: Run the same actions for every item received from a previous step.
  • Use current-item data: Map fields through Custom values > Loop Item.
  • Repeat a fixed number of times: Use a number range instead of a list.
  • Choose execution order: Run iterations sequentially or in parallel.
  • Review individual results: Inspect each iteration and its actions in the Test tab.

Action Name

The action appears in the workflow builder as Loop.

Action Description

Iterate over a list or a range of numbers and run the actions inside the Loop once for each item or number.

Action Details

These settings control what the Loop processes and how its iterations execute.

FieldDescriptionMandatory
Action NameName displayed on the workflow canvas. Defaults to Loop.Yes
Loop OverChoose A list of items or A range of numbers.Yes
ItemsList selected from a previous step, such as an inbound webhook array.For list loops
Start NumberFirst number in the range. Default: 1.For range loops
End NumberLast number in the range. Default: 10.For range loops
Execution ModeSequential by default. Enable Parallel to run multiple iterations at the same time.No

How to Configure

Configure the Loop after a trigger or action that provides the data you want to process.

Step 1: Add the Loop Action

Start in the sub-account where the workflow will run, and place the Loop after the step that provides its input data.

  1. From Sub-Account View, go to Automation > Workflows.
  2. Open an existing workflow or create a new one.
  3. Add and configure the trigger that provides the input data.
  4. Click the + icon where the Loop should start.
  5. Search for Loop in the Actions panel and select it.

Click the + icon where the Loop should begin.

Select Loop from the Actions panel.

Step 2: Choose What to Loop Over

Under Loop Over, select one option:

  • A list of items: Repeat the actions for each item in a list.
  • A range of numbers: Repeat the actions once for each number from Start Number to End Number.

Hover over the information icon beside a field to see its description.

Step 3: Configure the List or Range

The input determines which values the Loop can use. Choose a list from a previous step or define the numbers to repeat.

For a list of items:

  1. Select A list of items.

  2. Click the tag icon in Items.

  3. Open Previous steps.

  4. Select the trigger or previous action containing the list.

  5. Choose the list field, such as the services array from an Inbound Webhook Trigger.

Choose a list from a previous workflow step.

For a range of numbers:

  1. Select A range of numbers.

  2. Enter the Start Number.

  3. Enter the End Number.

  4. Review the helper text showing the total number of iterations.

For example, a range from 1 to 10 runs the actions inside the Loop 10 times.

Configure a number range and review the iteration count.

Step 4: Choose the Execution Mode

Under Execution Mode, choose how the iterations should run:

  • Sequential: The default mode. Each iteration finishes before the next begins.
  • Parallel: Enable the toggle to run several iterations at the same time.

Parallel execution can reduce processing time when actions depend on external systems.

Step 5: Save the Action

Click Save action. The Loop appears on the canvas with a dashed box for the actions that will repeat.

Step 6: Add Actions Inside the Loop

Click the + icon inside the dashed box and add the actions you want to repeat.

To use data from the current list item, click the tag icon in an action field and select Custom values > Loop Item. Choose a field such as Name, Estimated Value, Urgency, or Preferred Date.

These values change with each iteration.

Select the current item's fields through Custom values > Loop Item.

Note: The opportunity screenshots below show the older Create or update opportunity action. For new workflows, use Create Opportunity. The screenshots demonstrate how Loop Item values are mapped.

Opportunity Name and Opportunity Value mapped from the current item in the original example.

Map Loop Item fields to a task.

Use Loop Item values in a note.

Step 7: Review the Finished Loop

Only actions inside the dashed box repeat for each item. Actions placed below the box run once after the Loop finishes.

The original example shows three actions inside the Loop.

Confirm that each action is positioned correctly. Save your workflow and test it before publishing.

Behavior and Logic

Loop behavior depends on the input type, execution mode, and position of actions on the workflow canvas.

RuleWhat Happens
Number of iterationsOne iteration per list item or number in the selected range.
Sequential modeEach iteration finishes before the next starts.
Parallel modeSeveral iterations run at the same time.
Loop Item in a list loopContains the current item's fields. The values change with each iteration.
Loop Item in a range loopList-item fields are empty. Use the loop counter under Custom values > Loop Item for the current number.
Actions after the LoopRun once, after all iterations finish.

Testing the Loop

Run a workflow test to verify the input data, number of iterations, and results of the actions inside the Loop.

Run a Workflow Test

Use an event with representative data to confirm that the Loop processes the expected number of items and repeats only the intended actions.

  1. Open the workflow containing the Loop.

  2. Click Test workflow in the upper-right corner.

  3. On the New test tab, select Test using events.

  4. Under Select Trigger, choose the workflow trigger.

  5. Under Select event, choose a recorded event. If needed, enable Listen for events and trigger a new event.

  6. Review the event data and click Start test run.

  7. When the test finishes, select the Loop step on the canvas.

  8. Open its Test tab to review the results.

Important: Workflow tests execute real actions. Use test data to avoid unintended messages or changes to customer records.

Test workflow with an Inbound Webhook event.

Review Each Iteration

The Loop's Test tab provides the following information:

  • Input: Action Name, Items, Mode, and Loop Over values.
  • Output: Items, Succeeded, Failed, and Duration for the Loop.
  • Iterations: Each iteration, its status, and the actions executed inside it.

Use the arrows to move between iterations. Click the open icon beside an action to inspect its Input and Output for that iteration.

Review the results and actions for individual Loop iterations.

Use Case

A home services business receives an inbound webhook containing contact details and three requested services: Roof repair, Gutter cleaning, and Exterior painting. It wants to create a separate opportunity, task, and note for each service.

  1. Inbound Webhook: Receive the contact details and services list.

  2. Create contact: Map First Name, Email, and Phone from the webhook data.

  3. Loop: Select A list of items and choose the services array from the Inbound Webhook Trigger.

  4. Create Opportunity: Inside the Loop, select a pipeline and stage. Map Opportunity Name to Loop Item > Name and Opportunity Value to Loop Item > Estimated Value. Enable Duplicate Opportunity when separate opportunities are needed for the same contact.

  5. Add task: Map Loop Item > Name to the task title, the relevant service details to the description, and Loop Item > Preferred Date to the due date.

  6. Add notes: Map Loop Item > Name and Loop Item > Urgency into the note fields.

  7. Result: The Loop processes all three services. With duplicate opportunity creation enabled and the applicable account settings configured, it can create three opportunities, three tasks, and three notes.

Note: If multiple opportunities are needed for the same contact in the same pipeline, enable Allow Multiple Opportunities per Contact under Sub-Account Settings > Objects > Opportunities.

Frequently Asked Questions

Q: What is Loop Item?

Loop Item represents the current item being processed. Use Custom values > Loop Item to map its fields into actions inside the Loop.

Q: How many times will the Loop run?

Once for each list item or each number in the selected range. The number-range helper text displays the iteration count.

Q: What is the difference between Sequential and Parallel?

Sequential processes one iteration at a time. Parallel runs several iterations concurrently.

Q: Can I use Loop Item with a range of numbers?

Yes. Use the loop counter under Custom values > Loop Item. List-item fields are empty for range loops.

Q: Where can I review each iteration?

After a workflow test, select the Loop step and open its Test tab. Use the Iterations list and open icon to inspect individual action results.

Q: Where do list items come from?

From a previous workflow step that provides a list, such as an Inbound Webhook Trigger. Select the list through the tag icon in the Items field.

Q: Do actions below the Loop run for every item?

No. Only actions inside the dashed Loop box repeat. Actions below it run once after the Loop finishes.
