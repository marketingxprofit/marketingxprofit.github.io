WhatsApp Template Builder Update and Dynamic Media URLs

A rebuilt template builder with live phone preview, and media headers that resolve per contact at send time — so one approved template serves every contact's unique asset.

Send every customer their own invoice, ticket, or personalized image from a single template. No more cloning a template for every asset and waiting on Meta to approve each copy.

What's New

The updated builder changes how templates are created and previewed, while dynamic media makes it possible to personalize the file sent to each contact.

  • Rebuilt builder — Create templates using a guided two-step process, with a live phone preview while editing template details.

  • Live phone preview — see exactly how the message lands on WhatsApp as you type, before Meta ever sees it.

  • Dynamic media URLs — media header fields now accept custom fields and dynamic values that resolve per contact at send time.

  • Clear failure behavior — invalid or empty resolved values fail clearly. No silent wrong media sent.

Rebuilt Create and Edit Experience

The updated WhatsApp builder guides you through two steps: Set up template, followed by Template details. Configure the message content and review the live phone preview before submitting the template for approval.

Two-Step Template Creation

First, choose the template category and type, then click Next. On the Template details screen, configure the name, language, header, body, variables, and optional buttons.

How to Create a WhatsApp Template

Create a template from your MxP sub-account and review its content and sample values before submitting it to Meta.

  1. Open the applicable MxP Sub-Account and select Settings.

  2. Open WhatsApp, then Templates.

  3. Click Create Template, then select Blank Template.

  4. Under Set up template, choose the category and template type.

  5. Click Next.



  1. Enter the Template name and select the Language.

  2. Configure the header, message body, variables, and optional buttons.

  3. Enter sample values for variables where required.

  4. Review the Live preview and correct any validation errors.

  5. Click Submit for approval.

How to Edit a WhatsApp Template

Existing templates can be edited when their current status permits changes. Review the fields available in the editor before updating.

  1. From the sub-account, select Settings → WhatsApp → Templates.

  2. Find the template and open its three-dot menu.

  3. Select Edit template, if available.

  4. Update the available fields and review the Live preview.

  5. Click Update.



Consistent Across Authoring Surfaces

AI template generation now runs through the same builder end to end. The WhatsApp template builder opened from Reputation uses it too. One interface to learn, not three.

Create a WhatsApp Template With AI

AI template creation uses the updated builder and live preview to help you prepare and refine a message before submission.

  1. From the sub-account, open Settings → WhatsApp and select Create AI Template.

  2. Complete the initial template setup and continue to Generate template.

  3. Enter the Business name, select a Language, and Describe your use case.

  4. Choose a Tone and optionally enable Add Emoji.

  5. Review the generated content and live preview. Select Generate again if needed.

  6. Make any necessary edits and click Submit for approval.

Note: This update covers the Create / Edit builder. Template list and folder management shipped separately under a previous update.

Live Phone Preview

The initial Set up template screen displays an Example preview. On the Template details screen, the Live preview updates as you edit the header, body, media, and buttons. Dynamic values may look different for each contact when the message is sent.

Catching a layout problem in the builder costs you seconds. Catching it after Meta approval costs you another approval cycle.

If the preview appears blank or is not updating, confirm you are in the updated builder via Settings → WhatsApp → Templates → Create / Edit.

Dynamic Media URLs

Media header fields now accept custom fields and dynamic values — not just one static public URL. At send time the value resolves for that specific contact and Meta receives a concrete URL for that message.

One Template Instead of Many

Previously, a different image or document meant a different template — and every new template goes to Meta for approval. Now a single approved template serves every contact's unique asset. The approved template stays the same; only the resolved URL varies.

Supported Sending Surfaces

Dynamic media URLs are supported in WhatsApp template sending flows that accept media header values or overrides, including the surfaces below. Available mapping controls may differ by workflow.

  • Workflows

  • Conversations

  • Bulk Actions

  • Calendar Appointments

  • Reputation Review Requests

  • Missed Call Text Back

Clear Failure Behavior

A dynamic value that resolves to a supported, publicly accessible media URL meets the media-access requirement, but other template and sending restrictions still apply. An invalid or empty resolved value can cause the message to fail instead of sending the intended media.

What Resolves Successfully vs. What Fails

A valid media URL must be accessible to Meta without authentication. Use these examples to identify what needs to be corrected before retrying a send.

  • A publicly reachable HTTPS URL containing a supported media file can be used when sending the template.

  • Private Drive links or URLs that require a login — Meta cannot access them and the message will fail.

  • An empty field — fails clearly with no silent wrong media sent.

If sending fails with a message such as "please provide a valid public url", check the selected field mapping and the resolved value for that contact.

Confirm the value is not empty, points to supported media, and uses a publicly accessible URL that Meta can download without signing in.

Pair dynamic media with an image personalization service like NiftyImages and a single bulk action renders a unique image for every recipient. Build the design once with a name placeholder, map the URL to a custom field, and let it resolve per contact at send time.

How to Use Dynamic Media

Dynamic media works best when each contact's resolved URL is valid, publicly accessible, and matches the template's media type.

For per-contact documents (invoices, contracts, IDs)

Use a contact-specific URL to provide each customer with the document that belongs to their record.

  1. Store a publicly reachable HTTPS URL on a contact custom field.

  2. In your template's media or header field, map to that custom field instead of pasting a fixed URL.

  3. Send from a workflow, bulk action, or conversation. Each contact receives their own file.

Example: Use a Dynamic Media URL in the Builder

The updated builder supports dynamic values inside media URLs. For example, a numbered placeholder in a personalized image URL can be mapped to a contact field.

  1. Open the MxP Sub-Account and select Settings → WhatsApp → Templates.

  2. Create a template and continue to Template details.

  3. Under Header, select Image, Video, or Document, as applicable.

  4. Select Media URL.

  5. Enter a publicly reachable HTTPS media URL with a supported numbered placeholder where needed.

  6. Map the placeholder to the appropriate contact field using the variable mapping control.

  7. Enter a sample value and review the Live preview.

  8. Complete the template and click Submit for approval.



In the illustrated example, the URL contains {{1}}, which is mapped to {{contact.first_name}} with a sample value for the preview.

A contact custom field can also store an entire public media URL. That is a separate use case from a numbered placeholder inside the URL; available mapping or override controls depend on the sending flow.

For personalized images at scale

Create a single image design, then supply a dynamic URL so the image can be customized for each recipient.

  1. Create your image design in a service like NiftyImages, with a placeholder for the contact's name or any other detail.

  2. Use the personalized image URL as your media header value, with the contact's detail supplied dynamically via a custom field.

  3. Run a bulk action. Every contact receives an image rendered just for them.

Requirement: The resolved value must be a publicly reachable URL that Meta can download. Private Drive links, URLs behind a login, and empty fields will fail.

Why This Matters

Personalized media used to carry a hidden tax. Every variation meant another template, and every template meant another round of Meta approval before you could send anything. That made per-customer invoices, tickets, certificates, and personalized campaign images impractical for most businesses — so they either skipped them or built fragile workarounds.

  • Run personalized image campaigns at bulk scale instead of sending the same flat creative to everyone.

  • Send genuinely personalized documents without multiplying your template library.

  • Skip the approval queue for asset changes — the approved template stays the same and only the resolved URL varies.

  • Keep automations stable — workflows reference a dynamic value rather than a URL you hand-edit after every clone.

  • Catch layout mistakes before Meta sees them, with a preview that matches the real message.

Open Settings → WhatsApp → Templates, build one, and try a personalized image on your next bulk send.
