Automate Ticketing with Workflows

Use Workflows to assign requests, update ticket fields, send replies, record internal notes, and notify your team when something needs attention. Ticket triggers and actions let you build these processes around a specific support request.

Open Ticketing automations

Go to Tickets → Settings → Automation. The page lists workflows that start from or act on tickets, with their publication state and enrollment information.

Select Create workflow to start a workflow, or open an existing workflow to inspect its trigger and actions. You can also use the standard Automation area to manage workflows.

Use the Ticketing Automation page to find the workflows associated with support work.

Understand which ticket the workflow uses

A ticket-triggered workflow carries the ticket that caused the enrollment. Ticket actions and ticket custom values use that request as their context.

For example, a contact with a billing ticket and a technical ticket can enter a workflow for each request. An update should apply to the ticket associated with that enrollment, rather than every ticket belonging to the customer.

Find ticket changes which ticket subsequent ticket actions use. Handle its found and not-found branches deliberately so an update or reply is applied to the intended request.

Choose a trigger

TriggerUse it whenConfiguration to consider
Ticket CreatedA new request needs assignment, acknowledgment, or routingFilter by properties such as priority, category, status, assignee, or ticket name.
Ticket UpdatedA change needs follow-upUse change conditions such as has changed or has changed to where offered, then filter the resulting ticket state.
Customer Replied with Ticket as the reply channelA customer adds a reply to a ticketSelect the Ticket channel and apply ticket filters as needed.
SLA WarningA service target is approaching its deadlineChoose the applicable target and conditions; align the warning with your SLA configuration.
SLA BreachedA service target has been missedFilter the relevant target or policy and select the escalation action.

For an update workflow, decide whether you mean “priority is Urgent” or “priority changed to Urgent.” The first describes a state; the second identifies a change. This distinction helps prevent unrelated edits from starting the same process.

The workflow trigger is not a substitute for configuring the underlying SLA policy. Set the policy and its warning behavior first.

Choose ticket actions

Search for ticket in the workflow action picker. The Ticket actions include:

ActionWhat it does
Create ticketCreates a new request with the configured fields and contact.
Find ticketLocates a ticket using conditions and provides found/not-found paths.
Update ticketChanges properties on the ticket in context.
Assign ticketRoutes the ticket to the selected users using the action's assignment options.
Add internal note to ticketRecords team-only information on the ticket.
Send email reply to ticketSends a customer-facing reply associated with the ticket's email thread.

Use the ticket-specific email reply action when the message should be a reply on the ticket. Review the source mailbox, recipient context, and custom values before publishing an automation that sends email.

Build a ticket workflow

  1. Open Settings → Automation → Create workflow.
  2. Give the workflow a name that describes its outcome, such as Assign new billing tickets.
  3. Add the appropriate ticket trigger and its filters.
  4. Add a ticket action, notification, or condition from the action picker.
  5. Configure the action fields and use the custom-value picker where values should come from the ticket or contact.
  6. Review the branches, contact context, and ticket context.
  7. Save and test with a controlled example. Check the workflow's execution history and the resulting ticket.
  8. Publish when the workflow produces the intended result.

For workflows that begin outside Ticketing, establish the intended ticket with Find ticket before updating it, or create a ticket when the process is meant to open a new request.

Use conditions and custom values

Use If/Else to choose different paths based on ticket properties. For example, Billing requests can go to one group and Technical Support requests to another.

Use the custom-value picker to insert available ticket fields into replies and notifications, such as the ticket name, ID, priority, or link. Select values from the picker rather than typing an assumed variable name.

Check the not found branch of Find ticket. For example, a process can create a new request when none is found, while updating the found ticket when one already exists. If multiple matches are possible, choose the supported matching preference, such as the most recently created ticket.

Add an existing ticket to a workflow

From a ticket

  1. Open the ticket.
  2. Open Ticket actions in the top panel.
  3. Select Add to workflow.
  4. Search for and select the intended published workflow or workflows.
  5. Review the selection and select Add.

The enrollment picker lists published workflows. Review the destination before adding a ticket.

From the list page

Select the relevant tickets using their checkboxes, then choose Add to workflow from the bulk toolbar. Review the selected ticket count and chosen workflows before confirming.

Each selected ticket supplies its own ticket context. Review the workflow's re-entry settings and execution records when the same customer has multiple requests.

Avoid repeated or misdirected actions

Use narrow trigger filters and check the ticket's current state before sending an escalation or customer reply. The documented workflow model suppresses Ticket Updated triggers caused by workflow updates to help avoid loops; do not rely on repeated updates as a substitute for explicit workflow logic.

An SLA warning or breach is an event. A later status change does not necessarily remove an existing workflow enrollment. Use conditions to decide whether a later action still applies, especially before sending a follow-up after time has passed.

Frequently asked questions

Do I need a separate Ticketing automation engine?

No. Ticketing automation uses Workflows.

Can I start a workflow for an existing ticket?

Yes. Use Add to workflow from the ticket or from a selection on the list page.

Can one customer's tickets be handled differently?

Yes. Use each ticket's properties and enrollment context to route and handle the request separately.

Does an internal-note action email the customer?

No. Use the ticket email reply action when the workflow should send a customer-facing response.
