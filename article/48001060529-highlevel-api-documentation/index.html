MxP API Documentation

MxP provides APIs that allow developers to build custom integrations, automate processes, and connect external applications with the MxP platform.


The APIs support contacts, conversations, calendars, workflows, payments, webhooks, and more.

API access is available across MxP subscription plans. However, certain endpoints and capabilities may require a higher-tier plan.


Important: API V1 reached end-of-support on December 31, 2025. Existing integrations may continue working, but API V1 no longer receives updates or technical support. Developers are encouraged to use supported API versions.



For complete endpoint references, visit the Official MxP API Documentation.

MxP API Documentation


The official API documentation provides information about available endpoints, authentication, request parameters, response formats, and supported API versions. Developers can use this documentation to:

  • Explore available API endpoints.

  • Review authentication requirements.

  • Check supported API versions.

  • Build and maintain custom integrations.

  • Understand endpoint-specific restrictions.


Note: New legacy API key generation is being phased out. Private Integration Tokens and OAuth 2.0 are the recommended authentication methods.

How to Use Versioned API Documentation


Versioned API documentation allows developers to reference the correct API version when building or maintaining integrations.

  1. Open the MxP API Documentation.

  2. Select the required API version using the version switcher.



  3. Review the available endpoints, parameters, and response formats.

  4. Use the appropriate version when developing or updating integrations.


API V3 is available for supported endpoints. Availability varies by endpoint.

API Authentication Methods


MxP supports two primary authentication methods for modern API integrations.


Private Integration Tokens (PIT)


Private Integration Tokens allow developers to securely connect internal applications to MxP. They are suitable for account-specific integrations and allow permissions to be managed through assigned scopes.


OAuth 2.0


OAuth 2.0 allows applications to request authorized access to MxP accounts. It is commonly used for public integrations, Marketplace applications, and applications requiring user authorization.


Note: The availability of an authentication method does not guarantee access to every API endpoint.


For setup instructions, see Private Integrations: Everything You Need to Know.


What Are the API Rate Limits?


MxP applies rate limits to public API V2 requests using OAuth to maintain performance and stability.

Limit TypeLimit
Burst Limit100 requests per 10 seconds
Daily Limit200,000 requests per day


These limits apply per Marketplace application and resource (Location or Company).


Rate Limit Response Headers


API responses include headers that help developers monitor usage:


  • X-RateLimit-Limit-Daily

  • X-RateLimit-Daily-Remaining

  • X-RateLimit-Interval-Milliseconds

  • X-RateLimit-Max

  • X-RateLimit-Remaining


Note: These are the documented OAuth API V2 limits. Other APIs or Enterprise arrangements may have different limits.

Frequently Asked Questions


Q: Is API access available on all MxP plans?

Yes. MxP provides API access across Starter, Unlimited, and Founder plans. However, individual endpoints may have additional subscription requirements.


Q: Are OAuth 2.0 and Private Integration Tokens available on the Starter plan?

Yes. Both authentication methods are available across plans. Access to specific endpoints depends on permissions, scopes, and plan eligibility.


Q: What is the difference between Basic and Advanced API Access?

These terms describe API capabilities associated with subscription tiers. The specific endpoints available depend on the plan and endpoint-level restrictions.


Q: Does the Founder plan provide access to all API endpoints?

Not necessarily. Endpoint availability depends on the applicable subscription entitlements, scopes, and API-specific requirements.


Q: Which endpoints require a higher-tier subscription?

Create Sub-Account and Enable SaaS for Sub-Account are documented as Agency Pro-restricted endpoints. Refer to the current API documentation for additional restrictions.


Q: Is API V1 still supported?

No. API V1 reached end-of-support on December 31, 2025. Existing integrations may continue functioning, but updates and technical support are no longer provided.


Q: What authentication methods are supported?

MxP supports Private Integration Tokens and OAuth 2.0 for modern API integrations.


Q: Is API V3 available?

Yes. API V3 is available for supported endpoints. Developers should review the API documentation for version-specific availability.
