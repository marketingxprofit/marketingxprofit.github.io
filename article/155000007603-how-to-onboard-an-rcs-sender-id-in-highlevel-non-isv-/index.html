How to Onboard an RCS Sender ID in MxP (Non-ISV)

RCS Messaging · Twilio Setup
How to Register an RCS Sender ID in Twilio
Create the RCS Sender, set up a Messaging Service, connect the two, and share the details needed for onboarding.
Overview

This article describes the standard procedure for registering a Rich Communication Services (RCS) Sender ID using the Twilio platform: creating the sender, configuring its webhooks, attaching it to a Messaging Service, and sharing the resulting IDs with our team to complete onboarding.

Prerequisites

Before proceeding, ensure the following conditions are met:

✓  You have an active Twilio account that is enrolled in RCS.
✓  You have access to the sub-account for which the Sender ID is being created.
Note

RCS Sender IDs require approval from carriers and Google. This carrier/Google onboarding and approval process is outside the scope of this article.

Setup Guide
Procedure: 6 Steps in the Twilio Console
Follow the steps in order. Steps 1–3 create the sender, 4–5 build the Messaging Service, and 6 connects them.
2

Creating the RCS Sender ID

Step 1
Log In to the Correct Sub-Account
  1. Navigate to the Twilio Console.
  2. Log in to the sub-account for which you want to set up the RCS Sender ID.
Important

Ensure you are operating within the correct sub-account before proceeding, as Sender IDs are account-specific.

Step 2
Create the RCS Sender ID
  1. In the left-hand navigation, go to Develop → RCS → Senders.
  2. Click Create RCS Sender and complete the following required fields:
FieldDescription
Sender Display NameThe name that will be visible to message recipients
DescriptionA brief description of the sender / use case
Logo ImageYour brand logo (displayed in the messaging thread)
Banner ImageA banner image for your sender profile
Accent ColorBrand color used in the RCS message UI
Heads Up
  • Fill in any additional fields presented by Twilio as part of the registration flow.
  • Make sure to also share this information with our team.
Step 3
Configure Webhooks

Once the Sender ID is created, navigate to the Configuration tab and set the following URLs:

WebhookURLMethod
Incoming Messages URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/incomingPOST
Fallback URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/incomingPOST
Status Callback URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/statusPOST
Important

All webhook methods must be set to POST.

3

Creating a Messaging Service

Step 4
Create a Messaging Service
  1. Go to Develop → Messaging → Services.
  2. Click Create Messaging Service, enter a name, and select the appropriate option for "Select what you want to use Messaging for".
Tip

If Messaging is not visible in the navigation, click Explore Products and add it first.

Step 5
Configure Messaging Service Webhooks

Under the Integration step of the Messaging Service setup (Step 3 in Twilio's flow), configure the following:

Incoming Messages

FieldValueMethod
Request URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/incomingHTTP POST
Fallback URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/incomingHTTP POST

Delivery Status Callback

FieldValue
Callback URLhttps://backend.leadconnectorhq.com/phone-system/cpaas/v1/messages/status

Click Save once done.

4

Attaching the RCS Sender ID to the Messaging Service

Step 6
Add the RCS Sender to the Sender Pool
  1. Open the Messaging Service you just created.
  2. Navigate to the Sender Pool tab and click Add Senders.
  3. Under Sender Type, select RCS Sender and click Continue.
  4. Select your RCS Sender from the list and click Add RCS Senders.
Twilio Setup Complete

Your RCS Sender is now linked to the Messaging Service. The last step is sharing the details below with our team.

Frequently Asked Questions

Q: Can I start sending RCS messages as soon as I finish these steps?
No. RCS Sender IDs must also be approved by Google and the carriers. This article covers only the Twilio setup; the approval process is handled separately.
Q: Why does it matter which sub-account I use?
Sender IDs are account-specific. If you create the sender in the wrong sub-account, it won't be available to the Messaging Service and account you intend to connect, and you'll need to recreate it in the correct one.
Q: Why do I configure webhooks on both the RCS Sender and the Messaging Service?
Configuring both ensures that incoming messages and delivery status updates are routed correctly to the platform regardless of which Twilio resource handles the event. Use the exact URLs listed in Steps 3 and 5.
Q: Can I set the webhook method to GET?
No. All webhook methods must be set to POST (shown as HTTP POST in the Messaging Service settings).
Q: I don't see Messaging in the Twilio Console. What should I do?
Click Explore Products in the Twilio Console and add Messaging to your navigation, then return to Develop → Messaging → Services.
Q: What's the difference between the RCS Sender SID and the RCS Sender ID?
Both appear on the same sender page in Twilio. The SID starts with XE…, while the Sender ID starts with rcs:…. Share both with our team.
Q: What is the Friendly Name used for?
The Friendly Name is a label you choose. It's used only for display within the platform and isn't shown to message recipients.
