Managed Cloud Backend in AI Studio

Cloud in AI Studio gives your apps a built-in backend to store data, manage user accounts, and handle file uploads without connecting a separate backend service. Each project gets its own managed Cloud environment that can be configured directly within AI Studio. This article covers how to enable Cloud and manage its database, authentication, storage, security, and advanced settings.

What is Cloud in AI Studio?


Cloud is a managed backend for apps built in MxP AI Studio. It provides a database for saving information, authentication for managing app users, and file storage for uploads such as images and documents.


Cloud is created specifically for your project and can be managed from the AI Studio builder. You can view stored information, configure access, manage resources, and ask AI Studio to create database tables or policies without setting up a separate backend.


AI Studio also asks for your confirmation before building features that use Cloud.

How to Enable Cloud in AI Studio


Cloud can be enabled directly from your AI Studio project. Once activated, MxP provisions the backend services required for your application, which typically takes about a minute.


Prerequisite: Cloud supports projects built on TanStack Start. If you have an existing React project, go to Project Settings → Migrate to SSR first. Migration creates an upgraded copy while leaving your original live project unchanged. You must enable Cloud separately after migration.


  1. Log in to your account.

  2. Select AI Studio from the left-hand navigation menu.

  3. Create a new project by entering a prompt describing your app, or open an existing project.

  4. Once the project is ready, click More → Cloud in the AI Studio builder.

  5. Open Overview and click Enable Cloud.

  6. Wait for Cloud to finish provisioning. You can continue working on your project while setup runs.

  7. Once connected, the Cloud dashboard becomes available with the Database, Users, Storage, and Secrets options.

Note: If Cloud setup fails, your existing app remains unchanged. Click Try again to resume setup.


Cloud Overview Dashboard


The Cloud Overview dashboard provides a central location to monitor your project's backend and access its services. It displays the current connection status, database instance, and resource usage so you can quickly check the backend's condition.


Once Cloud is enabled, go to Cloud → Overview to access:


  • Connection Status: Displays whether your Cloud instance is connected.

  • Database: Shows existing tables and their record counts.

  • Users: Displays registered user counts and authentication settings.

  • Storage: Shows storage buckets used by your application.

  • Secrets: Provides access to the project's Secrets area.

Click on a section to access its detailed management page.


Database


The Database feature stores your application's structured data, such as user profiles, orders, and other records. It lets you manage the information saved by your app while using row-level security (RLS) policies to control which records users can access.


To manage your database, go to Cloud → Database.


Optimize the Database


Click Optimize on the Database page to send a database health-check request to AI Studio chat. This helps identify potential performance or efficiency improvements.


Note: Database optimization uses AI Studio credits, like other chat requests.


Manage Database Tables and Records


The Database page lists tables in your project's public schema, their approximate row counts, and their RLS policy status.


  • View records: Select a table to open its data.

  • Add records: Open a table and add new rows.

  • Edit records: Double-click a cell to modify its value.

  • Delete records: Select the rows you want to remove and delete them.

  • Update the schema: Ask AI Studio in chat to create or modify tables and policies. Schema changes are handled through AI Studio rather than direct schema editing in the database browser.


Manage Row-Level Security (RLS) Policies


RLS policies control which database records different users can access or modify. For example, a policy can allow signed-in users to view or update only their own orders.


  1. Open Cloud → Database.

  2. Click RLS policies.

  3. Review the policies associated with each table, including the policy name, command, applicable user role, and rule expression.

  4. To change a policy, describe the required access behavior to AI Studio in chat.


Manage Database Backups


Cloud automatically creates daily backups of your database schema and records.


  1. Go to Cloud → Database → Backups.

  2. Review the available database snapshots.

  3. Select the required snapshot and use Restore when you need to recover an earlier database state.


Important: Restoring a backup replaces the current live database with the selected snapshot. Database access is temporarily interrupted for a few minutes during restoration. Backups do not include uploaded storage files or application code. If the restored schema no longer matches your app, ask AI Studio to update the code.


Users and Authentication


Cloud includes user management and authentication settings for controlling how people access your application. You can monitor registrations, manage individual accounts, and configure security requirements for sign-ins and passwords.


Manage App Users


Go to Cloud → Users to access the user management dashboard.


  • Monitor signups: View registration activity using the Signups chart and its date-range filter.

  • Search users: Find registered users by email address.

  • Add users: Click Add user to create an already-confirmed account without sending an email.

  • Invite users: Use Send invitation to email a user a link to set their password.

  • View user details: Select a user to review their sign-in methods and account information.

  • Delete users: Open a user account and select Delete user to remove it permanently.



Configure Authentication Settings


Go to Cloud → Users → Auth settings to control how users sign in and register.


SettingFunction
Sign-in methodsConfigure supported authentication methods. The initial release supports email and password.
Allow new sign-upsEnable or disable new registrations without signing out existing users.
Anonymous usersAllow anonymous user authentication when enabled.
AdvancedAccess additional authentication configuration options.




Configure Email and Password Security


Under Auth settings → Email, you can configure the following options:


  • Minimum password length: Set the required password length (minimum 6 characters; 8 or more recommended).

  • Required password characters: Define which character groups passwords must contain.

  • Check against known breaches: Reject passwords found in publicly known data breaches.

  • Re-authenticate to change password: Require the current password before a user sets a new one.

  • Auto-confirm email: Skip email verification for testing purposes only.

  • Secure email change: Require confirmation through both the old and new email addresses.

  • Advanced: Configure available one-time code expiration and length settings.


Important: Email confirmation is required by default. Keep Auto-confirm email disabled for production applications.




Configure Authentication URLs


Authentication URLs determine where users are directed during login, registration, and account recovery.


  • Site URL: Set the primary URL for your application.

  • Redirect URLs: Add the URLs users can return to after authentication, including supported mobile deep links such as myapp://callback.


AI Studio handles preview URLs automatically. Ensure your configured URLs match the application URLs, as mismatches can cause authentication failures.


Storage


Cloud Storage manages files uploaded and used by your application, including images and documents. Files are organized into buckets, with access controlled by bucket visibility and row-level security policies.


Create and Manage Storage Buckets


  1. Go to Cloud → Storage.

  2. Click New bucket.

  3. Enter a bucket name containing 3–63 characters, using lowercase letters, numbers, and hyphens.

  4. Choose the bucket's visibility:

    • Public: Files can be accessed by anyone with the file link.

    • Private: Files are restricted to signed-in users, subject to access policies.

  5. Create the bucket to begin storing files.


Note: Bucket names cannot be changed after creation.




Manage Files


Open an existing bucket to perform the following actions:


  • Upload files and media.

  • Create folders to organize stored files.

  • Download or delete files.

  • Rename files.

  • Copy file URLs for use in your application.


Important: Renaming a file changes its URL. Update any references that use the previous URL.




Configure Upload Limits and Access


On the Storage page:


  • Use Upload size limit to define the largest file a bucket can accept. The default is 2 GB, with a maximum of 5 GB.

  • Click Save after updating the limit.

  • Open RLS policies to review the rules that control storage access.


Advanced Settings


Advanced settings let you control the resources allocated to your Cloud backend. You can increase database capacity, manage storage, pause unused resources, or permanently remove Cloud from a project.


Go to Cloud → Overview → Advanced settings to access these controls.


Manage Database Size


Cloud starts with the free Tiny database instance. You can change the instance size depending on your application's resource requirements.


Available sizes include:


  • Tiny

  • Mini

  • Small

  • Medium

  • Large

  • X-Large


Click Manage next to Database size to review available options and their hourly pricing.


Database size can be increased or decreased once per hour. Changes take a few minutes and briefly restart the application.


Manage Database Storage


Click Manage next to Database storage to increase allocated database space.


  • Database storage can be increased up to four times per day.

  • Allocated database storage cannot be decreased.

  • Charges are based on the allocated space and continue even when Cloud is paused.


File storage is billed differently: its usage increases or decreases with the files stored, and charges are based on the amount actually stored.


Pause or Resume Cloud


Click Pause under Pause Cloud to stop access to the Cloud backend while preserving its data.


Use Resume to reactivate a manually paused Cloud instance when needed.


If your account wallet cannot cover Cloud charges, Cloud pauses automatically without deleting its data. Once the billing issue is resolved, use Wake up to reactivate the instance. You can also move down to the free Tiny instance.


Remove Cloud


Click Remove under Remove Cloud to permanently delete the project's Cloud backend.


Warning: Removing Cloud permanently deletes the project's database, users, and stored files. Export database tables as CSV files and download any required files before removal. Other AI Studio projects are not affected.


Frequently Asked Questions


Q: Does enabling Cloud automatically update my published application?

No. Your existing published application remains unchanged until you publish the updated project again.


Q: What happens to Cloud data when I share or remix an AI Studio project?

Cloud data is not copied into the new project. However, the copied application may still send requests to the original project's Cloud backend, subject to its access rules.


Q: Are submissions from AI Studio forms connected to the MxP CRM automatically stored in Cloud?

No. Submissions from AI Studio forms connected to the MxP CRM are sent to the connected sub-account's CRM. Cloud database storage is a separate capability.


Q: Where are authentication emails sent from?

Signup confirmation, invitation, and password reset emails are sent through your account's email configuration. The links in these emails direct users back to your application.
