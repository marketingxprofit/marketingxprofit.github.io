Connect MxP MCP to Muse

MxP MCP is now available as an official app in Muse, giving Muse access to approved MxP CRM capabilities through Model Context Protocol (MCP). The connection uses OAuth, allowing you to choose the CRM sub-account(s) you want to connect and review the permissions requested before granting access. Once authorized, Muse can access 600+ supported operations across 38 CRM domains through four unified MCP tools, based on the scopes you approve.

What is MxP MCP for Muse?


MxP MCP for Muse creates a secure connection between Muse and MxP so Muse can interact with supported CRM services using Model Context Protocol. MCP provides a standardized way for compatible AI clients to discover available capabilities, retrieve information, and perform approved actions without requiring users to build separate integrations for each CRM function. MxP's MCP Server supports CRM services such as Contacts, Conversations, Calendars, Opportunities, Payments, Locations, and Custom Fields.


With the Muse integration, authentication is completed using OAuth through a dedicated MxP MCP endpoint:

https://services.leadconnectorhq.com/mcp/muse/v2/


During authorization, you select the CRM sub-account(s) Muse can connect to and approve the requested scopes. These scopes determine which MxP data and functionality Muse is authorized to access.

Key Benefits of MxP MCP for Muse


Connecting MxP to Muse gives you a controlled way to make supported CRM capabilities available to Muse while retaining visibility into the permissions being requested. OAuth scopes help limit access to the specific MxP resources and actions authorized during setup.

  • OAuth-based connection: Authenticate through MxP without manually configuring credentials for the Muse connection.

  • Sub-account selection: Choose the CRM sub-account(s) you want to make available during authorization.

  • Granular access control: Approve OAuth scopes that determine the MxP resources and actions Muse can access.

  • Broad CRM coverage: Access 600+ supported operations across 38 CRM domains.

  • Unified MCP access: Supported operations are exposed through four unified MCP tools, simplifying how Muse interacts with MxP.

  • Permission visibility: MxP's OAuth experience displays requested scopes so users can review the permissions an external application is requesting before authorizing it.

How OAuth Permissions Work with Muse


OAuth allows an external application to request access to specific MxP resources without requiring you to share account credentials directly with that application. Reviewing requested scopes before authorization helps you understand which areas of MxP Muse will be able to use and what types of actions may be available.


When you connect MxP to Muse, the OAuth authorization flow presents the permissions, or OAuth scopes, being requested. MxP's OAuth consent experience is designed to show users the requested permissions and explain what those permissions allow before access is granted.


OAuth scopes should not be confused with MxP user permissions:

  • OAuth scopes control what the Muse connection is authorized to access.

  • User roles and permissions control what an individual MxP user can access within a sub-account.

  • Assigned data restrictions can further limit which records a MxP user can view or manage. MxP supports Admin and User roles as well as granular module permissions and assigned-data restrictions.


Always review the requested OAuth scopes before approving the connection.

Supported MxP Operations


MCP allows compatible AI clients to work with MxP services through a standardized connection instead of requiring a separate integration for every supported CRM function. The Muse integration provides access to 600+ supported operations across 38 CRM domains through four unified MCP tools, with actual access determined by the OAuth scopes you approve.


MxP's general MCP Server supports services including:

  • Contacts

  • Conversations

  • Calendars

  • Opportunities

  • Payments

  • Locations

  • Custom Fields


MxP's MCP documentation also explains that MCP-compatible clients can retrieve records, update data, send messages, search opportunities, access calendar information, and perform other supported actions when appropriate access is available.


The exact operations available to Muse depend on the permissions granted to the connection. Approving only the scopes you need helps keep access aligned with your intended use case.

How To Set Up MxP MCP for Muse


A successful setup requires completing MxP's OAuth authorization flow, selecting the correct CRM sub-account(s), and reviewing the scopes requested by Muse. Confirming these settings during setup helps ensure Muse receives the intended level of CRM access.

  1. Open Muse and locate the option to connect an app or MCP service.

  2. Select MxP as the app you want to connect.


  3. When prompted for the MxP MCP connection, use the Muse-specific endpoint:

    https://services.leadconnectorhq.com/mcp/muse/v2/

  4. Start the MxP authorization process.

  5. Sign in to MxP if prompted.

  6. Review the MxP OAuth authorization screen.

    MxP's OAuth consent experience displays the application's requested scopes so you can understand the permissions being requested before approving access.

  7. Select the CRM sub-account(s) you want to connect to Muse.

  8. Review the requested OAuth scopes and confirm that they match the access you want Muse to have.

  9. Approve the authorization request.

  10. Return to Muse and confirm that MxP shows as connected.


Muse can now use the MxP operations available through the scopes you approved.

Frequently Asked Questions


Q: Do I need a Private Integration Token to connect MxP to Muse?
The Muse connection described here uses a dedicated MxP MCP endpoint and an OAuth authorization flow. Follow the OAuth process presented through Muse rather than the generic token-based setup documented for other MxP MCP client configurations.


Q: What determines which MxP operations Muse can use?
The available operations depend on the OAuth scopes approved during authorization. Scopes define which MxP resources and actions an external application can access.


Q: Can Muse make changes to data in MxP?
MxP's MCP Server supports both retrieving information and performing supported actions, including updating data, when the required access is available. Whether a specific action is available through Muse depends on the approved scopes and supported operation.


Q: Why do I need to review OAuth scopes before connecting?
OAuth scopes identify the MxP resources and actions an external application is requesting. Reviewing them helps you understand the access you are granting before completing authorization.


Q: Why can't I see the MxP sub-account I want to connect?
First verify that the MxP user completing authorization has access to the expected sub-account. MxP user roles and permissions determine what a user can access within individual sub-accounts.


Q: Are OAuth scopes the same as MxP user permissions?
No. OAuth scopes control the permissions granted to an external application, while MxP user roles and permissions control what an individual user can access inside a sub-account.


Q: Can I revoke Muse's access later?
MxP recommends regularly reviewing connected applications and revoking access to applications that are no longer needed. Connected application access can be reviewed from Settings > Connected Apps in MxP.


Q: Does every Muse connection automatically receive all 600+ MxP operations?
No. The integration supports 600+ operations across 38 CRM domains, but the operations available to a connection are based on the scopes approved during authorization.
