Eliza Agent Platform • Permissions • Contact Routing
Eliza Agent Platform Settings in MxP
MxP includes Eliza Agent Platform controls for managing user access and deciding which contacts are sent to Eliza. You can give users access to Eliza Service, exclude contacts with a bypass tag, selectively route contacts with a Send to Eliza tag, or send contacts immediately through a workflow. These controls help agencies manage Eliza routing directly from MxP.
What You'll Learn

Learn how to enable Eliza Service access, configure bypass and Send to Eliza tags, send contacts to Eliza through workflows, and troubleshoot common access and routing issues.

Important

The Send to Eliza tag and Send to Eliza Agent Platform workflow action do not behave the same way. The tag waits for a new inbound message, while the workflow action sends the contact to Eliza when that workflow step runs.

What Are Eliza Agent Platform Settings in MxP?

Eliza Agent Platform settings in MxP control user access and how contacts move from a MxP sub-account into Eliza.

These settings let you:

  • Give authorized users access to Eliza Service.
  • Prevent selected contacts from entering Eliza.
  • Send only selected inbound conversations to Eliza.
  • Send a contact to Eliza immediately through a workflow.

Connection Requirement: These settings work with a sub-account that has already been added to the Eliza Agent Platform.

2

Key Benefits of Eliza Agent Platform Settings

Eliza routing controls help agencies decide who can configure Eliza and which contacts should enter the platform instead of sending every conversation through the same process.

  • Control User Access: Give Eliza configuration access only to users who need it.
  • Exclude Selected Contacts: Use an Eliza Bypass tag when specific contacts should not enter Eliza.
  • Route Selected Contacts: Use a Send to Eliza tag when only certain inbound conversations should enter Eliza.
  • Automate Immediate Routing: Use a workflow action when a contact should be sent to Eliza without waiting for an inbound message.
  • Manage Routing from MxP: Configure core Eliza routing rules directly from the CRM.
3

Prerequisites and Limitations

Confirming Eliza access and routing requirements before configuration helps prevent missing settings and contacts being routed differently than expected.

  • The applicable MxP sub-account must already be added to the Eliza Agent Platform.
  • The user must have access to the applicable MxP sub-account.
  • Users who configure Eliza settings must have the Eliza Service permission enabled.
  • The user's email address should also be configured for the applicable location in the Eliza Agent Platform.
  • Create or identify the contact tags you want to use before configuring tag-based routing.

Routing Difference: A Send to Eliza tag waits for a new inbound message before routing the contact. The Send to Eliza Agent Platform workflow action sends the contact when that workflow step executes.

How To Enable Eliza Service Access

Eliza Service permission controls whether a user can access the Eliza settings available inside the assigned MxP sub-account.

  1. Switch to Agency View.
  2. Click Settings.
  3. Select Team.
  4. Locate the applicable user and open the user's settings.
  5. Open Roles & Permissions.
  6. Locate Eliza Service.
  7. Enable the permission.
  8. Save the user's changes.

After access is enabled, switch to the applicable sub-account and open:

Settings → Eliza Service

5

How To Configure the Eliza Bypass Tag

The Eliza Bypass tag prevents selected contacts from having new inbound conversations forwarded to the Eliza Agent Platform.

Create or identify the contact tag you want to use before configuring the routing rule.

  1. Open the applicable sub-account.
  2. Click Settings.
  3. Select Eliza Service.
  4. Locate the Eliza Bypass Tag setting.
  5. Select the tag you want to use.
  6. Save the configuration.

When a new inbound message arrives, MxP checks the contact for the configured bypass tag. If the tag is present, the inbound conversation is not forwarded to Eliza.

Existing Eliza Conversation: If the conversation is already in Eliza, it can be removed from the agent queue when the agent navigates to it. The closed conversation uses the Bypass tag assigned disposition.

6

How To Configure the Send to Eliza Tag

The Send to Eliza tag is useful when you want only selected contacts with new inbound conversations to enter Eliza.

  1. Open the applicable sub-account.
  2. Click Settings.
  3. Select Eliza Service.
  4. Locate the Send to Eliza Tag setting.
  5. Select the tag you want to use.
  6. Save the configuration.
  7. Apply the tag to contacts whose inbound conversations should be sent to Eliza.

You can apply the tag manually or through a workflow. For example, use an Add Contact Tag action when a contact meets your routing criteria.

Important: Applying the Send to Eliza tag does not immediately send the contact to Eliza. The contact is sent when a new inbound message is received.

If Both Tags Apply: When both the Eliza Bypass tag and Send to Eliza tag apply, MxP honors the Send to Eliza tag so the conversation is not unintentionally excluded.

7

How To Send Contacts to Eliza Using a Workflow

Use the Send to Eliza Agent Platform workflow action when a contact should be sent to Eliza as soon as the workflow reaches that step instead of waiting for a new inbound message.

Step 1: Open the Workflow

Start with the workflow and trigger that determine which contacts should be sent to Eliza.

  1. Open the applicable sub-account.
  2. Click Automation.
  3. Select Workflows.
  4. Open an existing workflow or create a workflow.
  5. Configure the trigger that determines which contacts should enter the workflow.

Step 2: Add the Send to Eliza Agent Platform Action

The Eliza workflow action sends the contact to the connected Eliza Agent Platform when execution reaches that step.

  1. Click the + icon where you want to add the action.
  2. Open the available workflow actions.
  3. Locate the Eliza Actions section.
  4. Select Send to Eliza Agent Platform.
  5. Configure the action as needed.
  6. Save the action.
  7. Save or publish the workflow.

Workflow Behavior: The Send to Eliza tag is not required for this workflow action to send the contact. If a Send to Eliza tag is configured for the location, that tag can also be applied before the contact is sent.

Troubleshooting

Most Eliza routing issues come from missing permissions, incomplete Eliza location access, or confusion between tag-based routing and the workflow action.

Eliza Service Does Not Appear in Settings

Check all required access conditions before assuming the Eliza connection is unavailable.

  1. Confirm the sub-account has been added to your Eliza Agent Platform account.
  2. Confirm the user has access to the applicable MxP sub-account.
  3. Confirm the same user's email address is configured for that location in the Eliza Agent Platform.
  4. Confirm Eliza Service permission is enabled for the user in MxP.

After correcting access, reload the sub-account and check Settings again.

A Tagged Contact Is Not Appearing in Eliza

If you are using the Send to Eliza tag, the contact must receive a new inbound message before the conversation is sent to Eliza. If the contact should be sent immediately, use the Send to Eliza Agent Platform workflow action instead.

A Contact Is Still Being Sent to Eliza

Confirm the configured Eliza Bypass tag is actually applied to the contact. Also check whether the contact is simultaneously meeting your Send to Eliza tag criteria. When both routing settings apply, MxP honors the Send to Eliza behavior.

Frequently Asked Questions

Q: What is the difference between the Send to Eliza tag and the Send to Eliza workflow action?
The tag routes the contact after a new inbound message. The workflow action sends the contact to Eliza when that workflow step executes.
Q: Does applying a Send to Eliza tag immediately send a contact to Eliza?
No. Tag-based routing waits until the contact sends a new inbound message.
Q: Can I send a contact to Eliza without waiting for an inbound message?
Yes. Use the Send to Eliza Agent Platform workflow action.
Q: Does the workflow action require a Send to Eliza tag?
No. The Send to Eliza tag is not required for the workflow action to send a contact to Eliza.
Q: What happens if both the Bypass and Send to Eliza tags apply?
MxP honors the Send to Eliza tag so the conversation is not unintentionally excluded.
Q: Why can't I see Eliza Service in the sub-account settings?
Confirm the sub-account is connected to Eliza, the user has access to that sub-account, the user's email is configured for the location in Eliza, and the user's Eliza Service permission is enabled in MxP.
Q: What does the Eliza Bypass tag do?
It prevents applicable new inbound conversations from being forwarded to the Eliza Agent Platform.
