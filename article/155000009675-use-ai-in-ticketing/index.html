Use AI in Ticketing

Use AI to catch up on a ticket, prepare a suggested reply, or improve wording you have already written. Connect your knowledge bases so suggested replies can use your support articles.

This guide covers ticket summaries, suggested replies, Polish my reply, and Knowledge base settings. Review generated content before using it in a customer response.

Choose the right AI tool

ToolWhen to use itWhere to find it
Summarize with AIYou need a shorter account of the request, work already done, and what is pending.Ticket top panel.
Suggest replyYou want a proposed response based on the ticket and available support context.The reply editor's AI controls; use More AI options when shown.
Polish my replyYou already have a draft and want help improving its wording.Reply editor.
Knowledge baseYou want suggested replies to use selected knowledge bases.Tickets → Settings → Knowledge base.

Available controls depend on the ticket state, configuration, and whether enough context is present. For example, an editor with an existing draft can show Polish my reply as the main AI action and Suggest reply in its adjacent menu.

Generate a ticket summary

  1. Open the ticket you want to review.
  2. Select Summarize with AI in the top panel.
  3. Read the summary card shown in the ticket's main area.
  4. Compare the summary with the relevant messages before making a decision.
  5. Use Regenerate when you need a refreshed summary, or dismiss the card when finished.

The summary helps an agent catch up; the original ticket messages remain the source for full context.

The summary can identify the customer's issue, what has been tried, and what the ticket is waiting on. If the history is too short or the tool cannot generate a useful result, review the ticket directly and try again when more context is available.

Generate and review a suggested reply

  1. Open the ticket and review its latest customer message.
  2. Use the public reply editor.
  3. Select Suggest reply. If Polish my reply is the main control, open More AI options to find Suggest reply.
  4. Wait for the suggested-reply card to finish generating.
  5. Read the proposed response and check names, facts, instructions, and any commitments it makes.
  6. Select Insert into reply if you want to use it, Regenerate for another suggestion, or Dismiss to discard it.
  7. Review and edit the content in the reply editor, then use Send reply when it is ready.

Use Suggest reply when you need a proposed response, and Polish my reply when you already have wording to improve.

The generated text is marked Draft — review before sending. Inserting and sending are separate actions.

If the editor already contains text, inspect the whole reply after insertion so it reads as one response and does not repeat a greeting or instruction. Review any source information shown on the card, and confirm the underlying material when the answer depends on it.

Polish an existing reply

Write your response in the editor, then select Polish my reply. Review the proposed wording or updated draft before sending it.

Check that the revision preserves your intended meaning, dates, prices, instructions, and promised next steps. Wording assistance does not verify the business facts in the response.

Connect knowledge bases

An administrator can select the support content Ticketing AI should use.

  1. Open Tickets → Settings → Knowledge base.
  2. Select Connect a knowledge base.
  3. Search for and select the relevant existing knowledge bases.
  4. Confirm the connection.
  5. Review the Connected knowledge bases list.
  6. Turn on AI suggested replies and enable the individual bases you want used for replies.

Connect relevant knowledge bases and enable the ones that should supply support content.

The connection picker identifies bases that are already connected. Use Open knowledge base to manage the underlying content in the Knowledge Base area.

Keep the knowledge content useful

Choose bases that apply to the product, service, and customers this support team handles. Keep policies and instructions current so generated drafts are based on the right information.

  • Enable or disable an individual base to control whether it is used for suggested replies.
  • Disconnect a base when it should no longer be connected to Ticketing.
  • Update the source content in the Knowledge Base area when an instruction or policy changes.
  • Review the draft even when a relevant knowledge base is connected; the answer must still fit the specific request.

Connecting a knowledge base does not send messages to customers. The agent still reviews and sends a public reply from the ticket.

Example workflow for an agent

A teammate hands you a ticket with several messages. Use Summarize with AI to understand the issue, then read the latest exchange to confirm the current question.

Generate a suggested reply using the available ticket and knowledge-base context. Insert the useful content, add the specific next step you can commit to, check the recipients, and send the reviewed response. Use an internal note for any team-only handoff information.

Troubleshooting

IssueWhat to check
Suggest reply is not the main buttonOpen More AI options. Existing text can make Polish my reply the primary action.
Suggested replies are unavailableCheck the AI suggested replies setting and whether you are using the public reply editor.
A knowledge base is missing from the connected listUse Connect a knowledge base and confirm that the expected base is available in this sub-account.
A base is connected but should not be usedCheck its individual switch or disconnect it from Ticketing.
A summary misses recent contextReview the latest messages and regenerate; do not rely on a summary without checking what happened afterward.
A draft gives an incorrect or incomplete answerEdit or discard it, check the source content, and verify the relevant facts before sending.
Generation failsReview the displayed error and try again. You can continue writing a response manually.

Frequently asked questions

Does AI automatically send the suggested reply?

No. Review the draft, insert the content you want to use, and send the reply separately.

What is the difference between a summary and a suggested reply?

A summary helps the agent understand the ticket. A suggested reply is proposed customer-facing wording.

Can I connect more than one knowledge base?

Yes. The settings page supports multiple connected bases with individual enable switches.

Will connecting a knowledge base guarantee the answer is correct?

No. It provides relevant support content, but the agent should still verify the proposed answer against the request and source material.

Is autonomous ticket resolution covered here?

This guide covers summaries and agent-reviewed reply assistance. It does not describe an autonomous resolution feature.
