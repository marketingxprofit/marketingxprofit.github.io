MxP Project Management API: Setup and Features

MxP's Project Management Public API allows developers to connect Project Management with other applications and automate everyday tasks. You can create project structures, manage tasks, update statuses, and control access without making every change manually in MxP. This article explains what the API supports, how it works, and how to get started.

What is the Project Management Public API?


The Project Management Public API lets developers manage MxP projects and tasks from other applications. With 45 endpoints across 8 API groups, you can create project structures, update tasks, manage permissions, and automate recurring work without making every change manually in MxP.

An API (Application Programming Interface) allows different applications to communicate and exchange information.


Availability: This API is currently available only to sub-accounts with Project Management Private Beta enabled.

Understanding the Project Structure


MxP Project Management uses a hierarchy to organize work. Understanding this structure helps you identify where projects and tasks belong when using the API.


  • Space: The main area for organizing projects.

  • Folder: An optional container that groups related Lists.

  • List: A collection of related tasks.

  • Task: An individual piece of work.

  • Subtask: A smaller task within another task.


For example, an agency could create a Space called Client Projects, a Folder called Website Projects, and a List called Website Launch containing tasks.

Note: Lists can be created directly inside a Space without using a Folder.


Managing Spaces, Folders, and Lists


The API lets you create and organize project structures from external applications.

You can:

  • Create, view, update, and delete Spaces, Folders, and Lists.

  • Create Lists inside a Space or Folder.

  • Retrieve large collections using pagination.

  • View direct and inherited member access.

  • Control privacy using isPrivate.

  • Grant or revoke member access.

Note: Adding members using userIds does not automatically remove existing access.


Managing Task Statuses


Statuses help teams track progress, such as To Do, In Progress, or Done. The API lets you retrieve and manage these statuses.


You can:

  • Retrieve the statuses available to a Space or List.

  • Replace a Space's complete status configuration.

  • Identify statuses using key and display them using label.

A task is considered complete when its statusGroup is done.

Managing Tasks and Subtasks


The API lets you create and manage tasks without entering them manually in MxP. You can also divide larger tasks into smaller subtasks.


You can:

  • Create, view, update, and delete tasks.

  • Search and filter tasks across up to 10 Lists.

  • Retrieve multiple tasks using their IDs.

  • Create subtasks using parentTaskId.

  • Add custom field values to tasks using Custom Fields V2.

Task searches can return subtasks as collapsed, expanded, or separate results.

Managing Tasks Across Multiple Lists


A task can appear in multiple Lists without creating duplicate tasks. This is useful when different teams need to track the same work.


You can:

  • View every List associated with a task.

  • Add or remove a task from a List.

  • Change the task's primary location, called its home List.

The home List determines which status configuration applies to the task.

Managing Task Comments


Task comments help team members discuss work and share updates. The API allows external applications to manage these conversations.


You can:

  • View, create, update, and delete comments.

  • Add formatted text and @mentions.

  • Create replies one level below a comment.

Note: Only the comment author can edit or delete their comment.

Managing Recurring Tasks


Recurring tasks help automate work that repeats regularly, such as weekly reports or monthly reviews.

You can create, retrieve, update, and delete recurring task definitions using the API.

Schedules use structured recurrence options rather than requiring raw RRULE strings.

For supported scheduling options, refer to the Project Management API Documentation.

How to Get Started with the Project Management Public API


To use the API, you need access to Project Management Private Beta, valid authentication credentials, and the required permissions.


Step 1: Confirm Private Beta Access


The API works only for sub-accounts enrolled in Project Management Private Beta.

  1. Open your MxP sub-account.

  2. Navigate to Contacts → Tasks.

  3. Check whether the new Project Management experience is available.

  4. Confirm that your sub-account has Private Beta access.

Important: Seeing Project Management in your account is a useful initial check, but Beta eligibility must be confirmed before using the API.



Step 2: Set Up Authentication


Authentication allows MxP to verify that your integration has permission to access data.

The API supports three authentication methods:


  • Private Integration Token (PIT): A token used to connect an external application to MxP.

  • OAuth: Allows an application to access MxP through an authorization process.

  • APP Channel: An authentication option for supported application integrations.


To create a Private Integration Token:

  1. Open Settings → Private Integrations at the appropriate account level.

  2. Click Create New Integration.

  3. Enter a name and description.

  4. Select the required permissions (scopes).

  5. Create the integration and securely copy the token.

Note: The available permissions depend on the API operations you want to use. Never expose your integration token publicly.


For detailed instructions, see Private Integrations: Everything You Need to Know.


Step 3: Configure Your API Request


An API request tells MxP which action you want to perform, such as retrieving a Space or creating a task.

Before sending a request:

  1. Select the required endpoint from the Project Management API Documentation.

  2. Include your authentication credentials.

  3. Add the required header: Version: v3.

  4. Provide any required parameters and permissions.


The sub-account is identified differently depending on the authentication method:

AuthenticationLocation identification
OAuthDetermined by the token
Private Integration TokenDetermined by the token
APP ChannelPass locationId as a query parameter


Step 4: Test an API Request


After configuring authentication, test the connection using an API operation.

  1. Open the Project Management API Documentation.

  2. Select an operation, such as retrieving Spaces.

  3. Follow the endpoint's request instructions.

  4. Include the required authentication and Version: v3 header.

  5. Send the request using an API client or integration.

  6. Check the response to confirm the request succeeded.


For your first test, retrieving existing information is a good option because it does not change project data.

If the request fails, check Private Beta access, permissions, authentication, and the required parameters.

Frequently Asked Questions


Q: Can all MxP users access the Project Management Public API?

A: No. The API is currently limited to sub-accounts enrolled in Project Management Private Beta.


Q: Can I use the API without coding experience?

A: Using the API directly requires basic knowledge of API requests. You can also work with a developer to build an integration.


Q: Can I create tasks automatically?

A: Yes. The API supports creating, updating, and managing tasks through external applications.


Q: Can the same task appear in multiple Lists?

A: Yes. A task can belong to multiple Lists while maintaining one home List.


Q: Why is my API request failing?

A: Check that your sub-account has Private Beta access, your credentials have the required permissions, and your request includes Version: v3.


Q: Do I need a Private Integration Token to use the API?

A: Not necessarily. The API also supports OAuth and APP channel authentication.


Q: Where can I find the complete list of API endpoints?

A: Visit the Project Management API Documentation for endpoint details, request parameters, and supported operations.
